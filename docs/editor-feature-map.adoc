[[task4]]
== Task 4: do textual datasets stay textareas?

*Yes for amendments, with four corrections to the issue text.*

* A textual dataset is edited through `TextAmendment`, whose payload is
  `dataset_code` plus `text` (a `String`) plus `position_on`, `notes` and
  `actions[]`. `SchemaNode.vue` renders a `String` leaf as a `<textarea rows="3">`,
  and `src/lib/form/ui.test.ts` asserts the payload `{ _class: 'TextAmendment', text }`
  with a two-paragraph value. So the text body is a plain textarea, as designed.
* The catalog marks seven publications `textual`, not five: rr251, bureaufax,
  coast-stations, list-v, list-viii, nnp, e212-icc (`src/lib/catalogs.ts`). The
  issue and Phase 4 list five. NNP also has typed entry classes, so it is
  reachable both ways; list-viii is textual because its typed class lacks
  `callsign` (`docs/draft-validation.adoc`). Update the issue text or the catalog.
* The textarea is ITU staff only. A member session submitting `TextAmendment` is
  refused (`worker/lib/submissions.ts:212`). A member state cannot amend a textual
  register through the web app; the legacy editor had no such restriction.
* The editor does not restrict the textarea to verbatim text: stage-2 checks only
  that the register is textual (`worker/lib/validation.ts:111`). Size and
  encoding limits are stated in `docs/submission-workflow.adoc:493` but were not
  traced to code here.

General-message prose also uses scalar or multilingual plain text controls.
PR #124 supplies the ontology changes for telephone, mid, custom title and SANC;
this PR adds complete corpus preservation evidence without duplicating those changes.

through the form and Worker lifecycle for every SANC, telephone, custom and mid
record. Single-field edit regressions additionally assert unrelated YAML bytes
remain exact. Calendar navigation and rendered dates stay within years 0000–9999.
These shipped when site batch PR #137 merged into `main`.

The Electron README archive notice remains pending until parity and deployment;
the Electron repository has not been archived. Live repository, D1, identity and translation
proof remain separate from local checks.

== Corpus preservation evidence

Corpus source: `itu-ob-data` checkout `2c0dae9c8094c3f97fa25526f05c9c908df54e26`.
The follow-up corpus checks cover every stored record in each relevant directory:
SANC 124, telephone_service_2 377, custom 105 and mid 6. The legacy
telephone_service directory has zero records. Assertions cover source YAML,
HTTP JSON, schema form state, Worker validation and saved YAML. The Node SQLite
suite additionally imports, saves, approves and reads the artifact for all 612
records. Synthetic edit/revert tests and workerd/D1 tests exercise source lifetime.
Large general-message fields use bounded gzip/base64 storage inside D1, with
plain YAML and objects restored at API and publication boundaries. Small records
retain their existing database representation.
The older legacy-issue counts in this map's initial assessment used a different
data layout and are not the counts of current canonical YAML records.
