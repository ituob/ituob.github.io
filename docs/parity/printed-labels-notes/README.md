## Separate decisions on the extra changes

### Incomplete-data banner: retained

The existing component defaults its `incomplete` prop to false. The issue page
now passes the loader's flag explicitly. The loader classifies completeness
from populated messages and amendments, independently of the metadata marker.
Preview checks and regression specs verify both metadata and the rendered notice:

| Issue | Data marks incomplete | Notice expected |
| --- | --- | --- |
| 669 | yes | present |
| 955 | no | absent |
| 1075 | yes, legacy metadata marker | absent: populated content |
| 1125 | no | absent |
| 1296 | no | absent |
| 1343 | no | absent |

Issue 669 is the only loader-incomplete issue in the OB 1350 fixture; the
remaining checked pages cover complete issues and the stale metadata marker.
This prop correction does not change the loader's existing completeness
classification. In particular, the legacy marker in issue 1075 coexists with
populated message data; the loader already classifies that issue as complete.
That pre-existing classification is not changed by this patch.

### Annex chronology: deferred

The PM required the proposed chronology/date policy to agree with the printed
OB before it could remain in this PR. The latest annex numbers are supported
for two publications, E.118 and E.212 MNC, but the E.212 position date remains
inconsistent between the stored timestamp and the printed OB. There is also no
corpus example confirming the proposed missing-date carry-forward rule.

Accordingly, the chronology change and its dedicated active tests are removed.
`src/lib/loaders.ts` is byte-for-byte identical to main and to the validated
build/audit inputs. The retained page hooks, printed-context helper/component,
and banner prop are unaffected. No new date conversion or fallback is shipped.

The [follow-up issue draft](annex-follow-up.md) records both primary printed
examples, the unresolved card item, and acceptance criteria. The
[reproduction specs](annex-follow-up-regressions.md) are preserved with that
follow-up, including the conflicting pinned-corpus expectation. These are not
claims that the deferred behavior passes on this PR.

The lane's task-agent guard requires Cortex or a person to create the follow-up
issue. No issue number or URL has been invented for the draft.
