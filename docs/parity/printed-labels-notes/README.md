## Separate decisions on the extra changes

### Incomplete-data banner: retained

The existing component defaults its `incomplete` prop to false. The issue page
now passes the loader's flag explicitly. The loader classifies completeness
from populated messages and amendments, independently of the metadata marker.
Preview checks and regression specs verify both metadata and the rendered notice:

| Issue | Data marks incomplete | Notice expected |
| --- | --- | --- |
| 669 | yes | present |
| 955 | no | absent |
| 1075 | yes, legacy metadata marker | absent: populated content |
| 1125 | no | absent |
| 1296 | no | absent |
| 1343 | no | absent |

Issue 669 is the only loader-incomplete issue in the OB 1350 fixture; the
remaining checked pages cover complete issues and the stale metadata marker.
This prop correction does not change the loader's existing completeness
classification. In particular, the legacy marker in issue 1075 coexists with
populated message data; the loader already classifies that issue as complete.
That pre-existing classification is not changed by this patch.

### Annex list: corrected following QA's pinned-corpus reproduction

The selector now pairs the latest annex OB number with that event's own stored
position timestamp. Pinned OB 1296 therefore lists `E212_MNC` at OB 1280,
`14.XI.2023`, from `ob-issues/1280/annexes.yaml`. The distinct `E212_ICC`
country-code publication retains its OB 1117, `1.II.2017` row. Earlier issue views
select only annex events published by that issue.

The official [OB 1283 English PDF, printed page 3](https://www.itu.int/dms_pub/itu-t/opb/sp/T-SP-OB.1283-2024-OAS-PDF-E.pdf)
confirms the latest annex numbers for both E.118 (OB 1283) and E.212 MNC
(OB 1280). The earlier
[OB 1161 English PDF, printed page 3](https://www.itu.int/dms_pub/itu-t/opb/sp/T-SP-OB.1161-2018-OAS-PDF-E.pdf)
lists E.118 at OB 1161. The new specs cover both publications, historical views,
newest-first ordering, and preservation of the separate country-code row.

This correction adds no carry-forward policy for an omitted date and changes no
date formatter. QA specifically expects the stored UTC timestamp to render as
`14.XI.2023`. The printed E.212 date is 15 November, while the E.118 timestamp
already renders its printed 31 December date correctly; that separate data/date
policy remains in the [narrowed follow-up draft](annex-follow-up.md).
